# Testing YouRec

Run commands from the repository root. Choose checks based on the behavior that
changed; do not redownload large model files for a UI-only fix.

## Build and model checks

```sh
./tools/build.sh :app:testEditor :app:assembleDebug :app:assembleDebugAndroidTest
```

The pure suite checks editing, undo, independent effect state, transition
source clocks and phases, handle limits, microphone identities and camera
capability selection. It does not need a connected phone.

## Device runner

Use `ANDROID_SERIAL` to choose a device explicitly:

```sh
ANDROID_SERIAL=SERIAL python3 tools/test-device.py
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --parity
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --exports
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --speech
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --studio
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --orientation
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --timeline
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --gaps
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --composition
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --camera-gaps
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --new-ui
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --hdr-color
ANDROID_SERIAL=SERIAL python3 tools/test-device.py --hdr-scene
python3 tools/check-hdr.py --device
```

The runner installs the app and instrumentation APKs without clearing app data,
grants camera/microphone access, and writes logs and captures to `artifacts/`.
Test project metadata is isolated under cache. After instrumentation the runner
returns to normal project storage. Recording tests create short
fixture recordings. Keep the phone unlocked and YouRec in the foreground.

* Default: native image/audio processing, decoding, stabilization, composition,
  export, camera switching, pause/resume, actual AF lock state, microphone names
  and portrait recording.
* `--parity`: portrait/landscape panels, drafts, cancellation, rotation,
  placement, volume removal, slider input and timeline workflows. Includes
  Settings card label bounds and toggles, plus Animate button layout. The name
  denotes the UI suite; passing it is not a pixel-equality comparison.
* `--exports`: transition frames, person-isolation ranges, 720p/1080p/4K output
  and a longer multitrack export.
* `--speech`: RNNoise and actual offline Qwen transcription; requires caption
  weights. See [MODELS.md](MODELS.md).
* `--studio`: neural restoration, filter order, ranges, mute, caching,
  cancellation, live changes and audio export; requires Studio weights.
* `--orientation`: asymmetric corner markers through 0/90/180/270-degree changes
  and different source sizes in one encoded file, plus real front/rear switching
  in portrait and landscape with either camera first. Real recorded pixels are
  compared against independently rotated raw ImageReader frames at 0/90/180/270
  degrees, allowing for stabilization crop and optical-center differences. Leave
  the phone stationary with both cameras facing a visible scene.
  Checks include audio/video timestamp alignment; playback dimensions alone do
  not prove upright content.
* `--timeline`: rendered thumbnail pixels move together across split boundaries
  when dragging in either direction, in portrait and landscape. Covers splits
  from one source and adjacent clips from separate sources, and verifies that
  scrolling leaves clip data unchanged.

* `--gaps`: both new audio models through the Android C API, ranges/mute/cache
  for all three neural effects, ordered multi-model processing, camera capability
  inventory, and native Kaleidoscope/Widescreen pixel checks. Install the
  separate audio models first with `tools/prepare-audio.py --install`.
* `--composition`: synthetic sources verify the recorded pixels of all four
  dual layouts, normal framing, swapped views and all four metadata orientations.
* `--camera-gaps`: actual concurrent front/rear recording, layout changes,
  pause/resume, audio/video timing and HEVC Main10 BT.2020/HLG metadata. Also
  decodes and exports the HDR file through the editor, and verifies capture
  effect changes retain their recorded ranges. Requires foreground camera access.
* `--new-ui`: live effect-sheet expansion, toggles and Clear all, Widescreen
  controls, 4:5 crop and independent quarter turns in both orientations.
* `--hdr-color`: generated 10-bit P010 patches in full and limited range through
  the GL preview, C11 converter, actual editor decoder and HEVC Main10 encoder.
  `tools/check-hdr.py --device` checks the encoded patch values independently
  with FFmpeg. The fixture is generated by `tools/hdr-fixture.py`.
  Synthetic paired scenes verify BT.2020, BT.709 and Display P3 detection and
  rejection of flat scenes. Corrected encoder output and older-file sidecars
  are decoded independently. Optional local `hdr-color-reference.png` and
  `hdr-color-input.png` files in the app's external files directory test the
  attached camera's confirmed BT.709 interpretation; personal images are not
  part of the committed fixtures.
* `--hdr-scene`: a short SDR/HDR scene comparison plus a direct HDR camera
  recording that bypasses the compositor. Keep the rear lens clear and still.
* `--audio-precision --precision fp32|fp16|fp16-storage`: isolated VoiceFixer
  loading, timing and finite-output checks on speech, quiet speech, noise and
  silence. Compare the saved waveforms against FP32 before accepting a format;
  a model can produce finite numbers and still corrupt the audio. See the
  [precision trial](VOICEFIXER_FP16.md) for conversion and comparison commands.

The latest local verification summary is kept in
[artifacts/validation.json](../artifacts/validation.json). APKs, raw captures,
logs and working references are local build artifacts, not repository content.

## Limits

The implemented effects and UI have not been certified as identical to the
original iOS application. Physical accessories, real alarm/call interruptions,
difficult person-segmentation footage and sustained thermal behavior need
broader testing. Capability-profile tests do not replace checks on other phones.
Caption timing is chunk-level. Short fixture performance is not a universal
quality or latency claim.

Test asset provenance is recorded beside the
[fixtures](../app/src/androidTest/assets/README.md).
